# متقن — Mutqen

منصة سعودية تربط الأفراد وأصحاب المشاريع بمستقلين **موثّقين عملياً** في استخدام الذكاء الاصطناعي، لإنجاز مهام **المحتوى** و**الميديا** و**البرمجة**.

العميل يكتب احتياجه بجملة، ومتقن يسأله أسئلة قصيرة، يكتب ملخص الطلب ومعايير القبول عنه، ويرشّح له ثلاثة مستقلين بسجلهم الفعلي على المنصة.

## الفكرة

| المشكلة | الحل في متقن |
|---|---|
| العميل ما يعرف يوصف وش يبي، فيتحول الطلب لتعديلات ما تنتهي | **ملخص موجّه:** جملة، ثم أسئلة باختيارات واختيارات بصرية ورفع ملفات، وينتج ملخص فيه المخرجات ومعايير القبول |
| العميل ما يعرف يفاضل بين عشرات العروض | **ثلاثة مرشحين** بسجلهم على المنصة ونماذج أعمالهم، أو «خلّ متقن يدير الطلب» |
| الخوف من الدفع لشخص ما تعرفه | **حجز المبلغ**، قبول خلال 24 ساعة أو استرداد تلقائي، وعيّنة أولى قبل التسليم الكامل |
| خلاف على وش داخل السعر | معايير القبول تحدد المشمول، والباقي **إضافة مسعّرة** يقبلها العميل أو يرفضها |
| ما أحد يعرف مين يتقن أدوات الذكاء الاصطناعي فعلاً | **اختبار عملي** بناتج حقيقي + مواقف في التعامل مع العملاء + مراجعة بشرية |

## الرحلات

**العميل**
1. `/brief`: جملة وحدة، ثم 5 إلى 6 أسئلة باختيارات، ثم الأسلوب والألوان والمراجع، ثم رفع الملفات (شعار، هوية، صور).
2. ملخص فيه «وش تستلم» و«معايير القبول»، يعدّله قبل ما يشوفه أي مستقل.
3. ثلاثة مرشحين: كم طلب مشابه أنجز، نسبة التسليم في الموعد، سرعة القبول، وعملاء رجعوا له. أو طلب مُدار برسوم ثابتة.
4. التسجيل عند الدفع. المبلغ ينحجز، والمستقل يقبل خلال 24 ساعة.
5. عيّنة أولى (تغيير الاتجاه مرة مشمول)، ثم التسليم الكامل والتعديلات ضمن الملخص، ثم الاعتماد والتقييم.
6. «عندي مشكلة» يوقف المؤقتات ويحوّل الطلب للإدارة.

**المستقل**
- تعبئة الملف من نص السيرة الذاتية، رقم الهوية، اختبار عملي بناتج مرفوع، واختبار مواقف في التعامل مع العملاء.
- بعد التوثيق: خدمات بثلاث باقات، معرض أعمال بالصور، وحساب تحويل (آيبان) قبل قبول أول طلب.
- يقبل أو يعتذر، يرسل العيّنة ثم التسليم، ويسعّر أي شي خارج الملخص كإضافة.

**الإدارة**
- `/admin`: اللي يحتاج قرار أولاً (خلافات، طلبات مُدارة، توثيق، طلبات متأخرة)، ثم المؤشرات.
- توثيق أو رفض بسبب مكتوب، وسحب التوثيق بسبب.
- `/admin/managed`: ترشيح مستقل وباقة لكل طلب مُدار.
- قرار الخلاف: استكمال، استرداد جزئي، أو استرداد كامل.

## الإيراد

| المصدر | القيمة | من يدفع |
|---|---|---|
| عمولة على الطلب المكتمل | 15٪، وتنزل إلى 10٪ بعد 3 طلبات مكتملة مع نفس العميل | تنخصم من المستقل |

## التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة والخادم | Next.js 15 (App Router، Server Components، Server Actions)، React 19، TypeScript |
| التصميم | Tailwind CSS 4، خط IBM Plex Sans Arabic، اتجاه RTL |
| قاعدة البيانات | PostgreSQL عبر Drizzle ORM (Neon أو Supabase)، ومحلياً PGlite مدمج |
| المصادقة | Better Auth (جلسات في قاعدة البيانات، أدوار: عميل، مستقل، مدير، واستعادة كلمة المرور بالبريد) |
| الذكاء الاصطناعي | أي مزوّد متوافق مع OpenAI Chat Completions، مع قواعد احتياطية تعمل بدونه |
| الاختبارات | Vitest للمنطق، Playwright للرحلات الكاملة، GitHub Actions |

### خدمات تتفعّل بمفتاح

كل خدمة خارجية اختيارية: الموقع يعمل بدونها، وتتفعّل بإضافة مفتاحها في إعدادات الاستضافة بدون تعديل على الكود. حالة كل خدمة تظهر للمدير في `/dashboard/settings`.

| الخدمة | المتغيرات | بدونها |
|---|---|---|
| الذكاء الاصطناعي | `AI_BASE_URL` `AI_API_KEY` `AI_MODEL` | بنك أسئلة ثابت وتقييم بالقواعد |
| البريد (Resend) | `RESEND_API_KEY` `EMAIL_FROM` | الإشعارات داخل الموقع فقط، واستعادة كلمة المرور غير متاحة |
| رفع الملفات (Vercel Blob) | `BLOB_READ_WRITE_TOKEN` | الملفات تُرفق كروابط |
| بوابة الدفع | `PAYMENT_PROVIDER` `PAYMENT_SECRET_KEY` | وضع الاختبار: كل الخطوات تعمل ولا يتحرك مال |
| رسائل الجوال (Authentica) | `AUTHENTICA_API_KEY` | توثيق الجوال غير متاح |

### حالات الطلب

```
awaiting_acceptance → in_progress (عيّنة) → sample_review → in_progress (كامل) → delivered → completed
                                                   ↘ revision_requested ↗
أي حالة مفتوحة → disputed → قرار الإدارة        |        awaiting_acceptance / تأخير → cancelled
```

كل انتقال عملية واحدة ذرّية تتحقق من الحالة المتوقعة، فالضغط المزدوج ما يكرر العملية، وكل تغيير ينسجل في `order_event`. المؤقتات (قبول 24 ساعة، اعتماد تلقائي بعد 3 أيام) تُنفَّذ عند قراءة الطلبات ومن مهمة مجدولة يومية (`/api/cron/sweep`).

## التشغيل محلياً

المتطلبات: Node.js 20 أو أحدث.

```bash
npm ci
cp .env.example .env      # ضع BETTER_AUTH_SECRET: openssl rand -base64 32
npm run db:migrate        # بدون DATABASE_URL تُستخدم قاعدة PGlite مدمجة في ./.pglite
npm run db:seed           # بيانات عرض (اختياري)
npm run dev               # http://localhost:3000
```

### بيانات العرض

`npm run db:seed` ينشئ مستقلين وعملاء وطلبات خيالية في كل حالات الطلب، لبيئة التجربة فقط. الإطلاق الفعلي يبدأ بقاعدة بيانات فاضية (`db:migrate` فقط).

كلمات المرور لا تُحفظ في المستودع. محلياً كلمة المرور `local-dev-only`، وعلى قاعدة بيانات مستضافة تُحدَّد من `SEED_PASSWORD` و`SEED_ADMIN_PASSWORD`.

| الدور | البريد |
|---|---|
| عميل | `buyer@mutqen.demo` |
| مستقل موثّق | `seller@mutqen.demo` |
| مستقل بانتظار التوثيق | `pending@mutqen.demo` |
| مدير | `admin@mutqen.demo` |

## الأمان

- كل عمليات الكتابة Server Actions تتحقق من الجلسة والدور وملكية السجل، وكل المدخلات تمر على Zod.
- الملخص ملك للحساب أو المتصفح اللي أنشأه، والطلب يشوفه طرفاه والإدارة فقط.
- حدود استخدام في قاعدة البيانات للمساعد، التوثيق، الطلبات، والرفع.
- الروابط المقبولة http(s) فقط، والتحويل بعد الدخول لمسارات الموقع فقط.
- إجابة اختبار المستقل تُعزل عن تعليمات المقيّم الآلي، والمحاولات الموجّهة للمقيّم تُرفض.
- رقم الهوية والآيبان لا يظهران لأي مستخدم، ويظهر للإدارة آخر 4 أرقام من الهوية.
