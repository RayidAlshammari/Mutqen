# متقن — Mutqen

منصة سعودية تربط الأفراد وأصحاب المشاريع بمستقلين **متحقَّق عملياً** من تمكنهم في أدوات الذكاء الاصطناعي، لإنجاز مهام **المحتوى** و**الميديا** و**البرمجة** في أيام بدل أسابيع.

> نسخة MVP: كل المسارات تعمل من البداية للنهاية، والدفع في وضع تجريبي، والبيانات المعروضة تجريبية.

## الفكرة

| المشكلة | الحل في متقن |
|---|---|
| العميل ما يعرف مين يستخدم الـ AI بإتقان ومين يلصق مخرجات آلية | كل مستقل يجتاز **مهمة عملية** في مجاله: يقيّمها الـ AI ثم تراجعها الإدارة، ويبيع في المجال اللي توثّق فيه فقط |
| العميل ما يعرف يكتب طلب واضح | **مساعد ذكي** يحوّل كلامه العامي لطلب منظم ويرشح أنسب الخدمات |
| الخوف من الدفع لشخص ما تعرفه | **حجز المبلغ (Escrow):** ما يتحول للمستقل إلا بعد موافقة العميل، مع استرداد كامل عند التأخير |
| المستقل ينتظر شهور بين المشاريع | سوق محلي يجيب له عملاء بشكل مستمر |

## المزايا

**العميل**
- مساعد ذكي (`/assistant`) يرتب الطلب ويرشح الخدمات، ثم يعبّي نموذج الطلب تلقائياً
- تصفح بفلاتر: المجال، وأداة الـ AI، والميزانية، ومدة التسليم
- خدمات بثلاث باقات، وملفات مستقلين بالتقييمات ونسبة التسليم في الوقت
- دفع تجريبي مع حجز المبلغ، ومتابعة الطلب، ورسائل، وتعديلات ضمن الباقة، وتقييم
- إلغاء واسترداد كامل إذا تأخر المستقل عن الموعد

**المستقل**
- توثيق بمهمة عملية تُقيَّم على 5 معايير، والحد الأدنى للقبول 60 من 100، ثم مراجعة بشرية
- حماية المقيّم الآلي من محاولات التلاعب (prompt injection)
- خدمات وباقات، ولوحة أرباح محوّلة ومحجوزة، وآيبان لتحويل الأرباح، وتعديل الملف بعد التوثيق
- إكمال تلقائي للطلب إذا ما رد العميل خلال 3 أيام من التسليم، عشان ما تتجمد أرباح المستقل

**الإدارة**
- مؤشرات: GMV، والإيراد، والـ Take rate الفعلي، والمبالغ المحجوزة، ونسبة العملاء المتكررين، وقائمة الانتظار
- مراجعة المستقلين وتوثيقهم، وكل الطلبات بفلترة حسب الحالة، وإلغاء إداري مع الاسترداد

## الرسوم

| | النسبة | مثال على باقة بسعر 1,000 ر.س |
|---|---|---|
| رسوم خدمة على العميل | 5% | يدفع العميل 1,050 |
| عمولة على المستقل | 10% | يستلم المستقل 900 |
| **إيراد المنصة** | ≈ 15% من قيمة الطلب | **150 ر.س** |

## التقنيات

| الطبقة | التقنية |
|---|---|
| الواجهة والخادم | Next.js 15 (App Router، Server Components، Server Actions)، React 19، TypeScript |
| التصميم | Tailwind CSS 4، خط IBM Plex Sans Arabic، اتجاه RTL كامل |
| قاعدة البيانات | PostgreSQL عبر Drizzle ORM. في الإنتاج Neon أو Supabase، ومحلياً PGlite مدمج |
| المصادقة | Better Auth (جلسات في قاعدة البيانات، أدوار: عميل، مستقل، مدير) |
| الذكاء الاصطناعي | أي مزود متوافق مع OpenAI Chat Completions (Gemini أو Groq أو OpenRouter)، مع وضع بديل يعمل بدون اتصال |
| التحقق من المدخلات | Zod لكل المدخلات على الخادم |
| الاختبارات | Vitest للمنطق، وPlaywright للرحلات الكاملة، وGitHub Actions للـ CI |

### البنية

```
المتصفح ──► Next.js
              ├─ Server Components     قراءة مباشرة من قاعدة البيانات
              ├─ Server Actions        كل عمليات الكتابة، مع تحقق الصلاحيات وZod
              ├─ /api/auth/*           Better Auth
              ├─ lib/ai.ts             ترتيب الطلب + تقييم مهمة التحقق
              ├─ lib/order-lifecycle   إكمال الطلب وتحويل المبلغ (ذرّي) + الإكمال التلقائي
              ├─ lib/rate-limit        حدود الاستخدام في Postgres (تعمل عبر serverless)
              └─ lib/authentica        رمز تحقق للجوال (اختياري)
                    ▼
              PostgreSQL: user · session · account · seller_profile · service · order
                          order_event · review · billing_profile · rate_limit · waitlist
```

**حالات الطلب:**
- `in_progress`: مدفوع والمبلغ محجوز
- `delivered`: سلّمه المستقل
- `revision_requested`: العميل طلب تعديل، ويرجع بعدها لـ `delivered`
- `completed`: اكتمل وتحوّل المبلغ للمستقل
- `cancelled`: أُلغي وأُعيد المبلغ للعميل

كل انتقال بين الحالات يتم في عملية واحدة ذرية، يعني ما يتنفذ إلا إذا كان الطلب فعلاً في الحالة المتوقعة، فالضغط المزدوج ما يكرر العملية. وكل تغيير ينسجل في `order_event`.

## التشغيل محلياً

المتطلبات: Node.js 20 أو أحدث.

```bash
npm ci
cp .env.example .env      # ضع BETTER_AUTH_SECRET: openssl rand -base64 32
npm run db:migrate        # بدون DATABASE_URL تُستخدم قاعدة PGlite مدمجة في ./.pglite
npm run db:seed           # بيانات تجريبية
npm run dev               # http://localhost:3000
```

### حسابات تجريبية
كلمة المرور لكل الحسابات: `Mutqen2026!`

| الدور | البريد |
|---|---|
| عميل | `buyer@mutqen.demo` |
| مستقلة موثّقة | `seller@mutqen.demo` |
| مستقلة بانتظار المراجعة | `pending@mutqen.demo` |
| مدير | `admin@mutqen.demo` |

### الذكاء الاصطناعي
بدون مفاتيح، يعمل المساعد والتقييم بمنطق بديل. ولتفعيل Gemini أضف في `.env`:

```bash
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
AI_API_KEY=...
AI_MODEL=gemini-3.5-flash-lite
```

## الاختبارات

```bash
npm run lint && npm run typecheck
npm test                    # اختبارات المنطق: الرسوم، الآيبان، الرقم الضريبي، الروابط، المقيّم الآلي
npm run build && npm run test:e2e   # الرحلات الكاملة على قاعدة مؤقتة جديدة في كل تشغيل
```

اختبارات الرحلات الكاملة تغطي:
- طلب كامل: المساعد ← الدفع ← التسليم ← التعديل ← الموافقة ← التقييم
- توثيق مستقل وحصره في مجاله
- الصلاحيات، والوصول لطلبات الآخرين، ورفض الروابط الخطرة
- التحقق من الآيبان والرقم الضريبي، وتوجيه كل دور
